# Онбординг пилотной компании — ранбук

Пошагово: как подключить одну компанию-клиента (её директора, менеджеров и АТС)
к CallControl так, чтобы через час у неё шли разобранные звонки. Ничего из этого
не требует правок кода. Секретов в этом файле нет и быть не должно.

Кабинет: `https://callcontrol-ai-demo.manukianartur1997.workers.dev/app/`

## 0. Один раз на платформу (не на клиента)

- [ ] **SQL применён.** Supabase → SQL Editor → вставить целиком
      `saas/migrations/APPLY_0004_0007.sql` → Run. Без этого биллинг, retention,
      Telegram, переключатель STT и RLS-фикс отвечают `503 migration_required`.
- [ ] Секреты воркера стоят (`wrangler secret list`): `SUPABASE_URL`,
      `SUPABASE_SECRET_KEY`, `ORG_SECRET_KEY`, `SIGNUP_CODE`, `PLATFORM_ADMIN_IDS`;
      для Telegram — `TELEGRAM_BOT_TOKEN`.
- [ ] Ты знаешь текущий `SIGNUP_CODE` (он нужен директору клиента для регистрации).

## 1. Организация клиента (владелец = их директор)

Два пути, выбери один:

- **Самостоятельно.** Директор открывает кабинет → «Зарегистрировать компанию»,
  вводит название, свой email, пароль и `SIGNUP_CODE`. Он становится `owner`.
- **Ты создаёшь за него.** Регистрируешь орг сам, затем приглашаешь директора
  с ролью `owner` (см. шаг 2) и отдаёшь ему ссылку. Себя потом можно понизить или удалить.

`owner` — единственная роль, которая трогает деньги и ключи (AI-ключ, STT, биллинг,
retention). `admin` управляет людьми и телефонией, но **не может стать owner**
(это закрыто миграцией 0006).

## 2. Команда и добавочные номера — самый важный шаг

Настройки → **Команда**: для каждого сотрудника email, роль, отдел и **добавочный
номер (extension)**.

- Extension = внутренний номер этого человека в АТС. Именно по нему входящий
  звонок из вебхука привязывается к менеджеру. Нет extension → звонок сохранится,
  но менеджер будет «неизвестен», и он не попадёт в рейтинг.
- Роли: `owner` → `admin` → `lead` (видит свой отдел) → `manager` (видит только
  свои звонки) → `viewer` (только чтение, без действий).
- Приглашение = ссылка (invite-by-link). Письма через встроенный SMTP Supabase
  идут **~2 в час** — на 10+ человек этого не хватит. Либо копируй ссылки и шли
  сам (Telegram/мессенджер), либо подключи Resend (раздел «Почта» ниже).

## 3. AI-ключ (owner)

Настройки → **AI-ключ**: провайдер Gemini, ключ из Google AI Studio (бесплатный
уровень достаточен для пилота), модель по умолчанию `gemini-flash-latest`.
Ключ хранится зашифрованным, в кабинете виден только хвост.

Пока ключа нет, звонки из АТС **не теряются**: они встают в `pending` с ошибкой
`ai_key_missing`. После добавления ключа открой звонок → «Повторить обработку».

## 4. STT: распознавание речи (опционально, owner)

По умолчанию — Gemini (дёшево, без чёткого разделения «менеджер/клиент»).
Настройки → **STT** → Deepgram + его API-ключ даёт настоящую диаризацию.
Без ключа выбрать Deepgram нельзя (кабинет честно попросит ключ). Если Deepgram
упадёт на конкретном звонке, воркер сам откатится на Gemini.

## 5. Телефония: вебхук в их АТС (owner/admin)

Настройки → **Телефония** → выбрать АТС → скопировать webhook URL → вставить в
кабинете АТС. Кнопка «Обновить токен» делает старый URL недействительным.

| АТС | Что нужно от клиента | Особенности |
|---|---|---|
| Ringostat | только вебхук | запись берётся по ссылке из вебхука |
| Binotel | вебхук + API key/secret в «Учётные данные» | запись тянется по REST; ack строго `{"status":"success"}` — это уже делает воркер |
| Phonet | вебхук + учётные данные | запись по REST с их авторизацией |
| UniTalk | вебхук, apiKey опционально | ключ прикрепляется **только** к хостам `*.unitalk.cloud` |
| Stream Telecom | вебхук, apiKey опционально | **не проверено вживую**: сверить формат по первому реальному событию (сырой payload лежит в audit_log) |

Пайплайн срабатывает только на **отвеченные** звонки; повторные доставки
вебхука дедуплицируются и не тратят квоту.

## 6. Чек-лист по умолчанию

**Чек-листы** → создать (или взять шаблон) → «Сделать по умолчанию».
Без дефолтного чек-листа звонок будет **транскрибирован, но не оценён**
(статус `transcribed`, причина `no_checklist`); после назначения чек-листа —
«Повторить обработку».

## 7. Telegram (owner/admin)

Настройки → **Telegram**: chat_id получателей. Два вида: `per_call` (пинг по
каждому разобранному звонку) и `daily` (дайджест-рейтинг менеджеров в
17:00 UTC = 20:00 Киев летом). Бот общий для платформы (`TELEGRAM_BOT_TOKEN`).

## 8. Биллинг и retention (owner)

**Биллинг**: ставка за минуту (по умолчанию 4 UAH/мин, валюта UAH/USD/EUR),
план, срок хранения сырых транскриптов (по умолчанию 90 дней; после — текст и
ссылки на записи стираются, оценки остаются). Шаблон DPA для клиента:
`docs/DPA_TEMPLATE.md` (перед отправкой — юристу).

## 9. Проверка «всё работает» (10 минут)

1. **Без АТС:** «Новый звонок» → вставить текст разговора → разобрать. Ожидаем
   оценку, чек-лист, утечки, коучинг.
2. **С аудио:** «Новый звонок» → загрузить запись (mp3/wav/m4a/ogg) → STT + разбор.
3. **С АТС:** сделать реальный отвеченный звонок → в «Звонках» статус
   `pending → transcribed → analyzed` за ~10–40 с → пинг в Telegram (если настроен).
4. **Деньги:** «Использование» — квота сдвинулась; «Биллинг» — появилась строка
   в леджере с минутами и стоимостью.
5. **Роли:** войти менеджером — видит только свои звонки; `lead` — свой отдел.

## 10. Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `503 migration_required` | SQL не применён | шаг 0 |
| звонок `pending`, `ai_key_missing` | нет AI-ключа | шаг 3 → «Повторить обработку» |
| звонок `pending`, `no_recording` | АТС не отдала запись / учётные данные добавили позже | проверить шаг 5 → «Повторить обработку» |
| `transcribed`, но без оценки | нет дефолтного чек-листа | шаг 6 → «Повторить обработку» |
| `failed`, `transcription_failed` | формат/битая запись | проверить, что АТС отдаёт аудио, не html-страницу |
| `quota_exceeded` | месячная квота орга | поднять `monthly_call_quota` (платформа) |
| вебхук отвечает 404 | токен/тип АТС не совпадают или интеграция выключена | пересоздать URL в шаге 5 |
| Binotel шлёт событие 7 раз | ack не тот | не должно быть — воркер отвечает `{"status":"success"}`; если повторяется — прислать сырой payload из audit_log |
| письма-приглашения не доходят | лимит встроенного SMTP | раздел «Почта» |

## Почта: снять лимит ~2 письма/час (Resend через Supabase)

Это настройка **в Supabase, не в коде**:

1. Resend → Domains → добавить домен → прописать DKIM/SPF-записи в DNS → дождаться Verified.
2. Resend → API Keys → создать ключ (sending).
3. Supabase → Project Settings → Authentication → **SMTP Settings** → Enable Custom SMTP:
   host `smtp.resend.com`, port `465`, user `resend`, password = API-ключ Resend,
   sender = адрес на верифицированном домене (например `noreply@ваш-домен`).
4. Сохранить → отправить тестовое приглашение.

Пока это не сделано — приглашения только ссылками вручную.
