# CallControl — план пилотного мини-SaaS

Статус: **черновик, ждёт команды «газ»**. Составлен 2026-08-08.
Цель: 2 реальные компании-пилота (Ringostat, Binotel) обкатывают продукт 1-2 недели
и дают фидбэк. Масштаб — до 10-50 клиентских компаний, без платёжки.

---

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Аналитика | Analytics Engine убрать. Clarity + Cloudflare Web Analytics | бесплатно, Clarity даёт записи сессий |
| Бэкенд | Supabase, второй бесплатный проект | RLS-паттерн уже отлажен в app-vibe-meter |

| Регистрация | **invite-only на пилоте** | снимает весь вопрос абьюза и IP-банов |

## Авторизация и иерархия

**Не писать руками — берём из Supabase Auth:**
email+пароль, magic link, Google, Apple, TOTP-двухфакторка — всё это конфигурация
и ~50 строк клиентского кода, а не разработка.

**Роли** (таблица `memberships`, проверка через RLS + custom claims в JWT):

| роль | видит | может |
|---|---|---|
| `owner` (директор) | всю организацию, все отделы, сводную отчётность | всё + биллинг + ключи |
| `admin` | всю организацию | заводить пользователей, чек-листы, настройки |
| `lead` (РОП) | только свой отдел | смотреть звонки отдела, коучить менеджеров |
| `manager` | только свои звонки | загружать, смотреть свои отчёты |
| `viewer` | read-only по своей области | ничего не меняет |

Ключевое: у `owner` отчётность **шире**, чем у `admin` — сводка по отделам,
динамика, сравнение РОПов. Админ — операционка, директор — деньги.

## Схема БД (Supabase / Postgres)

```
organizations      id, name, slug, plan, created_at
departments        id, org_id, name, lead_user_id
memberships        id, org_id, user_id, role, department_id, invited_by, status
invites            id, org_id, email, role, token, expires_at, accepted_at
calls              id, org_id, department_id, manager_id, source, external_id,
                   started_at, duration_sec, direction, status
transcripts        id, call_id, text, lang, provider, created_at
analyses           id, call_id, checklist_id, score, findings jsonb,
                   model, tokens_in, tokens_out, created_at
checklists         id, org_id, name, items jsonb, is_default
reports            id, org_id, period_start, period_end, payload jsonb
usage_counters     id, org_id, period, calls_analyzed, tokens_used, minutes
org_ai_keys        id, org_id, provider, key_encrypted, added_by, last_ok_at
dashboard_prefs    id, user_id, org_id, visible_widgets jsonb, order jsonb
audit_log          id, org_id, actor_id, action, target, meta jsonb, created_at
```

RLS: каждая таблица фильтруется по `org_id` из JWT. Изоляция организаций —
единственное, что нельзя сделать «примерно»; покрыть тестами обязательно.

## AI-слой

Адаптер с драйверами: **Gemini** (Google AI Studio — бесплатный вход),
Anthropic, OpenAI. Выбор провайдера и ключ — на уровне организации.

Два режима, переключатель в кабинете директора:
1. **Свой ключ** — организация вставляет API-ключ, платит напрямую провайдеру.
   Мы не в цепочке денег. Ключ шифруется, никогда не отдаётся обратно в UI.
2. **Наш ключ** — включено в тариф, лимит по организации. (после пилота)

Обязательное предупреждение в UI при бесплатном тарифе Google AI Studio:
данные с бесплатного тарифа могут использоваться для обучения модели.
Для транскриптов продаж это существенно — клиент должен решать осознанно.

## Дашборд

Не строить конструктор. Три уровня, делаем только первый:

- **Уровень 1 (делаем):** фиксированный набор 10-12 карточек-метрик,
  шестерёнка → включить/выключить/переставить. Сохраняется в `dashboard_prefs`.
- **Уровень 2 (по фидбэку):** пользовательские поля (сумма сделки и т.п.).
- **Уровень 3 (не делаем):** drag-resize сетка, формулы, кастом под клиента.

Дефолтный экран директора — не «много метрик», а: 3-5 цифр сверху
(где течёт выручка, сколько потеряно, худший/лучший отдел) + ранжированный
список проблем с конкретикой. Настройки — для тех, кому дефолт не подошёл.

**Граница продукта:** суммы сделок и статусы лидов не храним у себя —
подтягиваем из CRM клиента интеграцией. Иначе становимся плохой CRM
и конкурируем с KeyCRM/Bitrix.
